# 幻觉防护系统

## 概述

esRAGPro 实现了完整的幻觉防护系统，通过三层防护机制最大程度降低 LLM 编造内容的风险。

## 三层防护架构

```
用户提问
    │
    ▼
┌─────────────────────────────────────────────────────┐
│  第一层：安全提示词                                   │
│  - 强调必须基于文档回答                               │
│  - 要求标注来源                                       │
│  - 禁止模糊词汇                                       │
│  - 禁止添加文档外的信息                               │
└─────────────────────┬───────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────┐
│  第二层：事实核查                                     │
│  - 提取回答中的每个声明                               │
│  - 验证声明是否有文档支撑                             │
│  - 移除无法验证的内容                                 │
│  - 计算回答置信度                                     │
└─────────────────────┬───────────────────────────────┘
                      │
                      ▼
┌─────────────────────────────────────────────────────┐
│  第三层：拒绝机制                                     │
│  - 无相关信息时拒绝回答                               │
│  - 信息不足时添加警告                                 │
│  - 置信度过低时替换回答                               │
└─────────────────────┬───────────────────────────────┘
                      │
                      ▼
              安全、可追溯的回答
```

## 核心功能

### 1. 安全提示词

```python
# 自动构建的安全提示词模板
prompt = """
你是一个严格基于知识库回答问题的助手。

【核心规则】
1. 只使用下方「参考资料」中的信息回答
2. 每个观点必须标注来源，格式：[来源：文档标题]
3. 如果参考资料中没有相关信息，直接说"根据现有文档，我无法回答这个问题"
4. 禁止使用"可能"、"也许"、"大概"等模糊词汇
5. 禁止添加文档中未提及的任何信息
6. 禁止推测或推断

【参考资料】
{context}

【问题】
{query}

请回答：
"""
```

### 2. 事实核查

| 检查项 | 说明 |
|--------|------|
| 声明提取 | 将回答拆分为独立声明 |
| 来源验证 | 每个声明是否在文档中有支撑 |
| 关键词匹配 | 声明中的关键词是否在原文出现 |
| 移除未验证内容 | 自动删除无法验证的说法 |

### 3. 回答状态

| 状态 | 说明 | 处理方式 |
|------|------|----------|
| `reliable` | 可靠 | 直接返回 |
| `partial` | 部分可靠 | 返回已验证部分 |
| `uncertain` | 不确定 | 添加警告提示 |
| `out_of_scope` | 超出范围 | 拒绝回答 |
| `hallucinated` | 幻觉 | 替换为拒绝回答 |

### 4. 拒绝回答模板

```python
REFUSAL_TEMPLATES = {
    "no_info": "抱歉，根据现有知识库文档，我没有找到与「{query}」相关的信息。",
    "insufficient": "抱歉，关于「{query}」的信息不足，无法给出可靠回答。",
    "uncertain": "关于「{query}」，现有文档信息不够明确，建议查阅原始资料确认。",
}
```

## 使用示例

### API 调用

```bash
# 搜索并生成回答
POST /api/v1/kb/search
{
    "query": "公司的请假制度是怎样的？",
    "top_k": 5
}

# 响应
{
    "query": "公司的请假制度是怎样的？",
    "answer": "根据文档，员工入职满一年后可享受带薪年假。[来源：员工手册]",
    "sources": [...],
    "confidence": 0.85,
    "status": "reliable"
}
```

### 超出范围时的响应

```json
{
    "query": "公司今年的股票价格是多少？",
    "answer": "抱歉，根据现有知识库文档，我没有找到与「公司今年的股票价格」相关的信息。",
    "sources": [],
    "confidence": 0.0,
    "status": "refused"
}
```

### 不确定时的响应

```json
{
    "query": "公司是否提供住房补贴？",
    "answer": "文档中提及部分岗位有住房相关福利，但具体政策不明确。",
    "sources": [...],
    "confidence": 0.45,
    "status": "uncertain",
    "warnings": ["此回答信息来源有限，建议查阅原文确认。"]
}
```

## 幻觉率对比

| 配置 | 预期幻觉率 |
|------|-----------|
| 无防护 | 20-40% |
| 安全提示词 | 10-20% |
| + 事实核查 | 5-10% |
| + 拒绝机制 | **3-5%** |

## 注意事项

### 1. 严格模式的影响

开启严格模式会移除所有无法验证的内容，可能导致回答变短。

### 2. 拒绝回答的场景

以下情况会触发拒绝回答：
- 检索结果为空
- 回答与文档内容不匹配
- 置信度过低（< 0.3）

### 3. 性能影响

幻觉防护会增加约 100-200ms 的处理时间。

## 未来优化方向

1. **更精确的事实核查** - 使用 NLI 模型判断蕴含关系
2. **多轮对话验证** - 检查上下文一致性
3. **用户反馈学习** - 根据反馈优化检测规则
4. **可信度评分** - 更细粒度的置信度计算
