## 1. 使用规则

- 本文件把 PRD 的 73 条需求映射到：当前真实证明、拟定测试 ID、正例、反例、最终产物证明。计数：INT 7、VIS 6、FLR 5、SCN 7、EDT 9、EXP 6、CST 7、IOT 6、KNO 6、DEL 7、NFR 7；测试 ID 与需求 ID 一一对应。
- 本文件是“会话推导的实施基线”验收追溯，不是用户逐条签核；发布后只读。实现完成通过追加任务/验收记录引用同一基线（ID/版本/哈希 + 需求 ID），不改写本文件或 PRD，也不自动提升需求状态。
- **“未实现”不等于“不做”**：所有最终目标域（含明确延后的 IoT）都保留在验收范围内；分期只改变顺序。

- 测试 ID 规则：`T-<域>-<序号>`；执行时每个测试至少记录正例与反例，证据放入唯一目录，含原始 stdout、stderr、退出码、机器报告与必要的截图/哈希。
- 测试状态：`未执行` / `已执行-通过` / `已执行-失败` / `阻塞`。本基线所有未来测试均为**未执行**，除非明确引用现有证据。

## 4. 必测场景（逐项执行，不得以单元测试替代）

### S-01 “只改沙发”保持其他对象不变

- **映射**：EDT-003/EDT-007、SCN-001/SCN-005。
- **步骤**：载入含沙发、茶几、边柜的已保存 revision → 只修改沙发位置或材质 → 保存 → 对比前后 revision。
- **通过**：仅沙发目标字段变化；其他对象 ID、变换、材质签名、工程量与预算行不变；新 revision 的 parent 正确；undo 可恢复。
- **失败**：任一其他对象变化、ID 漂移、工程量变化、parent 错误、产生半写文件。
- **证据**：前后 revision JSON diff、对象 ID 清单、undo 报告、截图。

### S-02 “厨房不要动”作为不可变约束

- **映射**：INT-003/INT-006、INT-007。
- **步骤**：业主将“厨房不要动”标为硬约束 → 代理/批量编辑尝试移动或删除厨房对象 → 用户显式解锁后再次编辑。
- **通过**：首次尝试被拒绝且说明原因；约束保持冻结；解锁需用户确认并生成新版本；全过程留痕。
- **失败**：隐式解锁、静默跳过无提示、生成结果覆盖厨房、无审计记录。
- **证据**：约束状态、拒绝日志、解锁确认、版本 diff。

### S-03 “不喜欢某颜色”不得推断为“不喜欢风格”

- **映射**：INT-005、INT-007。
- **步骤**：输入“不喜欢这个橙色沙发”与参考图 → 生成替代方案 → 检查偏好记录与解释。
- **通过**：否定偏好只作用于颜色/该对象维度；风格、材质、布局不被标记为否定；如需外推必须标注推断并请求确认。
- **失败**：整屋风格被改写；其他维度被当作否定；无确认即固化推断。
- **证据**：偏好记录、推断标注、方案对比、确认记录。

### S-04 预算与功能冲突必须要求权衡

- **映射**：INT-004、CST-004/CST-005。
- **步骤**：需求含超出预算的功能组合 → 系统生成减项/换材/分期等权衡选项与成本增量 → 用户选择。
- **通过**：不静默超预算；每个选项有成本与影响说明；选择形成新版本；未选择时保持待定。
- **失败**：自动选默认方案、隐藏超预算、编造价格、无来源的成本增量。
- **证据**：权衡方案、预算报告、用户选择、版本 diff。

### S-05 实时相机/灯光/碰撞的来源隔离

- **映射**：EXP-001..005、VIS-001/VIS-005、SCN-001/SCN-005。
- **步骤**：进入人尺度运行时 → 移动/转向/碰撞 → 切换昼夜与模拟灯/窗帘 → 保存退出 → 对比 canonical 场景清单。
- **通过**：运行时使用独立视口/世界；设计几何、对象 ID、相机、源灯光、GLB/相机/灯光清单不变；模拟状态独立保存；逐帧移动不写盘、不增长 undo；保存/暂停/退出最多一次位姿事务。
- **失败**：运行时节点挂到 canonical 根、源几何/材质被改、相机/灯光清单漂移、逐帧写盘、模拟写成真实回执。
- **证据**：源清单前后对比、运行时报告、位姿/事务日志、独立进程重开。

### S-06 缺价必须是未知而非 0

- **映射**：CST-002/CST-003。
- **步骤**：构造含缺价行、显式 0 行、正价行的预算 → 查看小计/正式总价/UI → 补齐缺价后再看。
- **通过**：缺价行显示“未报价”，不计入小计，`complete=false`、`formal_total=null`；显式 0 计入且已知；补齐后才可能完整。
- **失败**：缺价按 0 计、自动填市场价、缺价时仍出正式总价、显式 0 与缺价混同。
- **证据**：预算报告 JSON、UI 截图、补齐前后对比。

### S-07 离线设备不得显示为已确认

- **映射**：IOT-002/IOT-005、IOT-004。
- **步骤**：模拟设备离线 → 发出控制指令 → 注入超时/失败 → 检查状态与日志。
- **通过**：显示离线/待确认/失败，不显示在线或成功；无回执不升级 `acknowledged`；设计文档不变；凭据不出现在状态/日志/证据。
- **失败**：绿色在线、显示“已开启”、模拟写成设备回执、凭据泄漏。
- **证据**：状态转换日志、协议回执、凭据扫描、设计文档对比。

### S-08 保存并重开旧方案

- **映射**：DEL-003、EDT-007、EXP-005、SCN-005。
- **步骤**：载入旧 210-object 文档（无 `project_state`/无体验状态）→ 普通保存 → 独立进程重开 → 对比字节与对象清单。
- **通过**：对象/ID/工程量保持；缺失字段保持缺失，不静默回填；新 revision parent 正确；体验状态只在显式保存后出现。
- **失败**：旧文档被改写、对象丢失、默认状态被写入、重开不一致、孤儿 revision。
- **证据**：旧文档哈希、重开报告、对象清单、revision 链。

### S-09 过期基线必须拒绝

- **映射**：KNO-005、SCN-005、KNO-003。
- **步骤**：任务携带旧版本/旧哈希 → 当前基线已更新 → 提交变更。
- **通过**：拒绝写入，提示基线过期与刷新路径；当前指针不变；无部分写入。
- **失败**：接受旧基线、覆盖新版本、静默合并、指针被未授权移动。
- **证据**：拒绝日志、base 哈希、指针历史。

### S-10 esRAG 写/读不一致必须显式失败

- **映射**：KNO-002/KNO-004、L 节协议。
- **步骤**：写入需求/决策记录 → 回读全文/分节 → 人为制造哈希或分节不一致 → 触发重试/人工处理。
- **通过**：界面显示失败状态，不显示“已同步”；保留本地权威文件；记录失败回执与重试路径。
- **失败**：伪造成功回执、用本地文件冒充已入库、静默丢弃失败。
- **证据**：写入请求、回读内容哈希、失败回执、本地文件哈希。

### S-11 实现 worker 自报不能批准发布

- **映射**：KNO-001/KNO-005、DEL-007。
- **步骤**：worker 提交“已完成/建议发布”但缺少规定证据或独立评审 → 发布门禁检查。
- **通过**：门禁保持阻塞；需要独立 reviewer 裁决与完整证据；自批标记被拒绝。
- **失败**：自报即发布、状态改为已验收、绕过缺失门禁。
- **证据**：任务提交、门禁结果、独立评审记录。

### S-12 视觉与打包补充测试

- **视觉**：运行中连续捕获 + 多视点 + 参考对比；离线 Cycles 图与旧 UI 截图不得替代（VIS-001..006、EXP-006）。
- **打包**：最终产物在空 cwd、无源码回退、独立进程重开、依赖缺失负例（DEL-001/005）。
- **性能**：加载/编辑/漫游/保存剖析；阈值未确认前只记录，不判定通过（NFR-001、VIS-006）。
