# 企业 RAG 幻觉率从 30% 降到 3% 的实战方案

## 背景：为什么企业不敢用 RAG

很多企业在试用 RAG（检索增强生成）后发现一个致命问题：**AI 会胡说八道**。

典型的场景：
- 员工问"公司报销流程是什么"
- AI 回答"提交发票给财务部，3天内处理"（听起来很合理）
- 但实际公司规定是"提交发票+审批单，5个工作日处理"
- 员工按 AI 说的做，结果被财务退回

这就是 **幻觉问题**——AI 会自信地编造不存在的信息。

据测试，普通 RAG 的幻觉率高达 **20-30%**。对于企业知识库，这是不可接受的风险。

---

## 我们的解决方案：三层幻觉防护

经过 3 个月迭代，我们实现了一套三层防护系统，将幻觉率降到 **3-5%**。

### 第一层：安全提示词

强制 LLM 遵守"只能基于文档回答"的规则：

```
你是企业知识库助手，必须遵守以下规则：
1. 只能基于提供的文档回答，禁止添加文档外的信息
2. 每个事实必须标注来源 [来源：文档标题]
3. 如果文档中没有相关信息，回答"抱歉，知识库中没有相关内容"
4. 禁止使用模糊词汇：可能、也许、大概、应该
5. 回答必须简洁、准确、可验证
```

这一层能降低约 50% 的幻觉，但还不够。

### 第二层：事实核查

在 LLM 回答后，系统自动验证每个声明：

```python
def verify_answer(answer, sources, context):
    # 1. 提取回答中的所有事实声明
    claims = extract_claims(answer)

    # 2. 检查每个声明是否有文档支撑
    verified_claims = []
    for claim in claims:
        supporting_doc = find_supporting_document(claim, sources)
        if supporting_doc:
            verified_claims.append(claim)
        else:
            # 移除无法验证的声明
            removed_claims.append(claim)

    # 3. 计算置信度
    confidence = len(verified_claims) / len(claims)

    return VerifiedAnswer(
        answer=verified_claims,
        confidence=confidence,
        status=get_status(confidence)
    )
```

关键点：**无法验证的内容会被自动移除**。

### 第三层：拒绝机制

根据置信度决定最终处理：

| 置信度 | 状态 | 处理方式 |
|--------|------|----------|
| ≥ 80% | reliable | 直接返回 |
| 50-80% | partial | 返回已验证部分，添加警告 |
| < 50% | uncertain | 替换为"信息不足，建议查阅原文" |
| 无相关文档 | refused | 拒绝回答 |

## 技术架构

```
用户查询
    ↓
混合检索（BM25 + 向量 + RRF融合）
    ↓
三层幻觉防护
    ↓
安全回答（可追溯来源）
```

核心组件：
- **检索层**：Elasticsearch 8.12 混合检索
- **防护层**：事实核查 + 拒绝机制
- **生成层**：DeepSeek-V3 / 通义千问 / 智谱 GLM
- **数据层**：PostgreSQL + Neo4j（GraphRAG）
- **部署**：Docker Compose 一键部署

## 效果对比

测试数据：1000 条企业知识问答

| 方案 | 幻觉率 | 回答完整度 | 用户满意度 |
|------|--------|-----------|-----------|
| 普通 RAG | 28% | 85% | 62% |
| + 安全提示词 | 15% | 78% | 70% |
| + 事实核查 | 8% | 70% | 85% |
| + 拒绝机制 | 3% | 65% | 92% |

有趣的是：**用户满意度反而上升**。因为用户宁愿得到"不知道"的诚实回答，而不是一个看似正确但实际错误的答案。
