# esRAGPro 风险与挑战清单

> 本文档记录产品规划过程中识别的风险、挑战和待解决问题。
> 用途：提醒团队注意潜在陷阱，避免遗忘。
>
> 创建日期：2026-03-17
> 来源：第一性原理分析

---

## 1. 核心假设验证清单

### 1.1 已挑战的假设

| 原假设 | 挑战结果 | 新认知 |
|--------|---------|--------|
| 企业需要 95% 准确率 | ❌ 部分错误 | 企业需要「可信任」，不只是准确率 |
| ES 混合检索是护城河 | ❌ 错误 | 技术是入场券，执行和关系是护城河 |
| 不限定客户，先跑通 | ❌ 错误 | 高价值客户才有付费意愿 |
| 卖软件授权 | ❌ 不够准确 | 卖「信任」和「风险控制」 |

### 1.2 待验证的假设

| 假设 | 验证方法 | 状态 |
|------|---------|------|
| ES 混合检索能达到 95% | 用真实数据集评测 | 🔴 未验证 |
| 金融/国企愿意为「可信」付费 | 客户访谈 | 🔴 未验证 |
| 「可追溯」功能能满足合规要求 | 法务/合规专家咨询 | 🔴 未验证 |
| 本地部署成本在客户可接受范围 | 成本估算 + 客户访谈 | 🔴 未验证 |

## 2. 技术风险

### 2.1 准确率相关风险

| 风险 | 级别 | 说明 | 缓解措施 |
|------|------|------|---------|
| **95% 定义模糊** | 🔴 高 | 不同指标（Recall/NDCG/端到端）结果差 10%+ | 明确评测指标，对客户透明说明 |
| **数据集偏差** | 🔴 高 | 自测数据集可能偏简单，客户真实数据效果差 | 用公开权威数据集 + 多领域数据集 |
| **中文效果差距** | 🟡 中 | ES 中文分词、Embedding 中文效果不如英文 | 选型时重点测试中文，备选方案 |
| **领域适配难** | 🟡 中 | 金融/法律/医疗术语，通用 Embedding 效果差 | 支持领域微调，或领域专用模型 |

### 2.2 技术方案风险

| 风险 | 级别 | 说明 | 缓解措施 |
|------|------|------|---------|
| **ES 9.0 不稳定** | 🟡 中 | 新版本生产案例少，可能有坑 | 先用 ES 8.12 验证，保留降级方案 |
| **技术方案可复制** | 🔴 高 | 混合检索方案公开，竞品 2 周可复制 | 加速执行，抢占客户心智 |
| **向量检索性能瓶颈** | 🟡 中 | 大规模数据（>1000万）ES 向量性能下降 | 降级到 Milvus/Qdrant 方案 |
| **文档解析坑深** | 🟡 中 | PDF 表格、扫描件、手写体难以处理 | MVP 只支持纯文本，逐步扩展 |

### 2.3 技术债务预警

| 债务 | 说明 | 何时还 |
|------|------|--------|
| RRF 参数调优 | 不同场景最优参数不同 | 评测阶段确定基准参数 |
| Embedding 模型选型 | 中文效果、私有部署、推理速度需平衡 | PoC 阶段对比测试 |
| 索引设计 | 分片策略、Mapping 设计影响性能 | 产品化阶段优化 |

## 3. 市场风险

### 3.1 竞争格局风险

| 风险 | 级别 | 说明 | 应对策略 |
|------|------|------|---------|
| **大厂入场** | 🔴 高 | 阿里/腾讯/字节都有企业级 RAG 产品 | 差异化：本地部署 + 可追溯 + 专业服务 |
| **开源替代** | 🟡 中 | Dify/FastGPT 等开源方案 | 强调「开箱即用」+「企业级支持」 |
| **客户自研** | 🟡 中 | 大企业有技术团队自研 | 提供「更快上线」价值，降低自研动机 |

### 3.2 客户相关风险

| 风险 | 级别 | 说明 | 缓解措施 |
|------|------|------|---------|
| **客户教育成本高** | 🔴 高 | 客户不理解「混合检索」价值 | 用案例和对比演示，不说技术细节 |
| **决策链条长** | 🟡 中 | 国企/央企决策慢，周期长 | 先做小规模 PoC，降低决策门槛 |
| **预算受限** | 🟡 中 | 中小企业买不起本地部署 | 提供 SaaS 版本（轻量方案） |
| **数据质量差** | 🔴 高 | 客户知识库质量差，再好的检索也没用 | 提供数据清洗/治理服务（增值） |

## 4. 商业风险

### 4.1 商业模式风险

| 风险 | 级别 | 说明 | 应对策略 |
|------|------|------|---------|
| **收入不稳定** | 🔴 高 | 软件授权一次性收费，无持续收入 | 年费模式 + 运维服务订阅 |
| **部署成本不可控** | 🟡 中 | 客户环境千奇百怪，部署耗时 | 标准化部署脚本 + 收取部署服务费 |
| **价格战** | 🟡 中 | 竞品可能低价抢市场 | 强调价值而非价格，建立口碑 |

### 4.2 团队能力风险

| 风险 | 级别 | 说明 | 应对策略 |
|------|------|------|---------|
| **销售能力不足** | 🔴 高 | toB 销售需要专业团队 | 创始人先亲自跑客户，积累经验 |
| **交付能力不足** | 🟡 中 | 项目交付需要工程能力 | MVP 功能克制，避免过度承诺 |
| **技术支持压力** | 🟡 中 | 客户问题响应慢影响口碑 | 建立知识库、文档、FAQ |

## 5. 产品风险

### 5.1 功能风险

| 风险 | 级别 | 说明 | 缓解措施 |
|------|------|------|---------|
| **过度承诺** | 🔴 高 | 客户期望「万能」，实际有边界 | 明确告知边界，管理预期 |
| **幻觉无法根除** | 🔴 高 | LLM 本质会产生幻觉，无法 100% 消除 | 强调「可追溯」，让用户自行判断 |
| **实时性差** | 🟡 中 | ES 近实时，知识更新有延迟 | 告知更新周期，支持手动刷新 |

### 5.2 用户体验风险

| 风险 | 级别 | 说明 | 缓解措施 |
|------|------|------|---------|
| **答案太长** | 🟡 中 | LLM 回答冗长，用户不想看 | 支持摘要模式、要点模式 |
| **引用打断阅读** | 🟡 中 | 过多引用影响阅读体验 | 提供引用折叠、悬停查看 |
| **置信度难理解** | 🟡 中 | 用户不理解「置信度」含义 | 用通俗语言：「非常确定/基本确定/仅供参考」|

## 6. 安全风险（红蓝对抗分析）

> 来源：Red Team vs Blue Team 安全分析

### 6.1 攻击威胁风险

| 风险 | 级别 | 攻击场景 | 缓解措施 |
|------|------|---------|---------|
| **数据投毒** | 🔴 高 | 恶意员工注入错误信息文档 | RBAC + 审批流程 + 监控审计 |
| **提示词注入** | 🔴 高 | 用户输入恶意指令绕过限制 | 输入过滤 + 输出过滤 + 架构隔离 |
| **对抗样本** | 🟡 中 | 构造语义相似但无关的文档 | 混合检索 + Reranker + 质量检测 |
| **DoS 攻击** | 🟡 中 | 大量并发请求耗尽资源 | 限流控制 + 资源隔离 |

### 6.2 数据安全风险

| 风险 | 级别 | 说明 | 缓解措施 |
|------|------|------|---------|
| **敏感信息泄露** | 🔴 高 | LLM 输出薪资、密码等敏感信息 | 敏感词过滤 + 权限控制 |
| **越权访问** | 🔴 高 | 用户查询无权限的文档 | 数据权限过滤（行级权限）|
| **内部威胁** | 🟡 中 | 有权限的员工恶意操作 | 审计日志 + 异常行为监控 |

### 6.3 安全功能实现优先级

| 功能 | 优先级 | MVP 必须 | 说明 |
|------|--------|---------|------|
| RBAC 权限控制 | P0 | ✅ 是 | 核心安全基础 |
| 审计日志 | P0 | ✅ 是 | 合规必需 |
| 限流控制 | P0 | ✅ 是 | 防止滥用 |
| 敏感词过滤 | P1 | 否 | 增强安全 |
| 文档审批流程 | P1 | 否 | 防投毒 |
| 用户反馈闭环 | P1 | 否 | 持续改进 |

### 6.4 安全事件响应预案

```
安全事件处理流程：
├─ 发现：监控告警 / 用户反馈 / 人工发现
├─ 确认：安全团队评估影响范围
├─ 止损：
│   ├─ 下线恶意文档
│   ├─ 封禁问题账号
│   └─ 回滚受影响数据
├─ 通知：
│   ├─ 内部：技术/产品/法务
│   └─ 外部：受影响客户（如需要）
├─ 复盘：
│   ├─ 分析根因
│   ├─ 改进防护措施
│   └─ 更新文档和培训
└─ 追踪：监控类似攻击是否再次发生
```

## 7. 风险等级说明

| 级别 | 说明 | 处理优先级 |
|------|------|-----------|
| 🔴 高 | 可能导致项目失败或重大损失 | 立即处理，必须有应对方案 |
| 🟡 中 | 会影响进度或质量，但可控 | 计划中处理，有预案 |
| 🟢 低 | 影响较小，可接受 | 可后续处理 |
