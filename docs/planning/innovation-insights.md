## SCAMPER 分析总结

### 高价值洞察

| 视角 | 洞察 | 优先级 | 阶段 |
|------|------|--------|------|
| **Combine（组合）** | 文档 + 数据库双知识源 | 🔥🔥🔥 高 | MVP 差异化 |
| **Modify（放大）** | 极致可追溯 = 极致可信 | 🔥🔥🔥 高 | MVP 核心 |

## 详细洞察

### 1. Combine（组合）- MVP 差异化核心

**洞察：支持「文档 + 数据库」双知识源**

```
┌─────────────────────────────────────────────────────────────┐
│                    双知识源架构                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  用户问题                                                    │
│     │                                                       │
│     ▼                                                       │
│  ┌─────────────┐                                            │
│  │ 意图识别    │                                            │
│  └──────┬──────┘                                            │
│         │                                                   │
│    ┌────┴────┐                                              │
│    ▼         ▼                                              │
│ ┌──────┐  ┌──────┐                                          │
│ │文档库│  │数据库│                                          │
│ │检索  │  │查询  │                                          │
│ └──┬───┘  └──┬───┘                                          │
│    │         │                                              │
│    └────┬────┘                                              │
│         ▼                                                   │
│  ┌─────────────┐                                            │
│  │ 结果融合    │                                            │
│  └──────┬──────┘                                            │
│         ▼                                                   │
│  ┌─────────────┐                                            │
│  │ LLM 生成    │                                            │
│  └─────────────┘                                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**实现要点：**
- 文档检索：ES 混合检索
- 数据库查询：Text-to-SQL
- 意图识别：判断问题类型（查文档 vs 查数据）
- 结果融合：统一格式返回

**商业价值：**
- 竞品大多只支持文档，这是差异化
- 企业真实场景确实两者都需要

### 2. Modify（放大）- 极致可追溯

**洞察：可追溯不只是显示原文，而是完整的推理链路**

```
┌─────────────────────────────────────────────────────────────┐
│                    可追溯层级                                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  Level 1：显示原文片段 ✅ MVP 必须                           │
│  ─────────────────────────────                              │
│  • 答案下方显示引用的原文                                    │
│  • 点击可查看完整文档                                        │
│                                                             │
│  Level 2：显示置信度分解 ✅ MVP 必须                         │
│  ─────────────────────────────                              │
│  • BM25 分数：X.XX                                          │
│  • 向量相似度：X.XX                                         │
│  • 最终 RRF 分数：X.XX                                      │
│                                                             │
│  Level 3：显示推理链路 🔮 未来迭代                           │
│  ─────────────────────────────                              │
│  • 哪个关键词触发了哪段文档                                  │
│  • 为什么选这段，没选那段                                    │
│  • 答案的每个部分来自哪里                                    │
│                                                             │
│  Level 4：可交互验证 🔮 未来迭代                             │
│  ─────────────────────────────                              │
│  • 用户可以标记「这段不对」                                  │
│  • 系统根据反馈重新检索                                      │
│  • 多轮对话逐步逼近正确答案                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**核心原则：极致的可追溯 = 极致的可信**

---

### 3. Eliminate（消除）- 聚焦核心

**洞察：MVP 阶段必须砍掉的功能**

| 功能 | 决定 | 原因 |
|------|------|------|
| Rust 重写 | ❌ 先不做 | 先验证 ES 方案，后期再做 |
| GraphRAG | ❌ 先不做 | 太复杂，投入产出比低 |
| 多模态（图片/表格）| ❌ 先不做 | 文档解析坑深，先支持纯文本 |
| 复杂权限系统 | ❌ 先不做 | 基础 RBAC 足够 |
| 工作流集成 | ❌ 先不做 | 先做好核心检索 |

**MVP = 检索 + 可追溯 + 安全**

---

### 4. Put to Other Uses（其他用途）- 增值服务

**洞察：RAG 引擎可以衍生出其他产品**

| 衍生产品 | 描述 | 商业模式 |
|---------|------|---------|
| **知识库质量检测工具** | 扫描知识库，找出矛盾、过时、重复内容 | 一次性服务费 |
| **培训材料生成器** | 从知识库自动生成培训材料 | 订阅制 |
| **合规审计助手** | 自动检索法规，对比企业实践 | 高端定制 |
| **智能客服引擎** | API 形式提供检索能力 | 按量计费 |

---

### 5. Reverse（反转）- 未来探索

**洞察：反过来思考，发现新可能**

| 反转视角 | 洞察 | 潜在价值 |
|---------|------|---------|
| **知识推送** | 不是用户搜文档，而是文档找用户 | 可能是更大的市场 |
| **用户验证答案** | 不是 LLM 生成，而是用户确认 | 持续学习，提升效果 |
| **个人版** | 不是企业付费，而是员工个人付费 | 降低获客门槛 |
| **按效果付费** | 不是一次性收费，而是按查询量/效果 | 降低客户决策门槛 |
