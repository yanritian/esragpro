## 二、技术选型决策

### 后端技术栈

| 组件 | 选型 | 备选 | 决策理由 |
|------|------|------|---------|
| **后端框架** | Python FastAPI | Node.js, Go | 快速开发，生态丰富 |
| **检索引擎** | Elasticsearch 8.12 | ES 9.0, Milvus | 稳定成熟，混合检索支持 |
| **业务数据库** | PostgreSQL | MySQL | 关系数据存储，扩展性好 |
| **Embedding 模型** | BGE-M3 | OpenAI, M3E | 中文效果好，可私有部署 |
| **LLM** | 客户自带 | OpenAI, Claude | 满足私有部署需求 |
| **缓存** | Redis | - | 会话缓存、热数据 |

### 前端技术栈

| 组件 | 选型 | 备选 | 决策理由 |
|------|------|------|---------|
| **前端框架** | Vue 3 | React | 开发效率高 |
| **UI 组件库** | Element Plus | Ant Design Vue | 企业端组件丰富 |
| **状态管理** | Pinia | Vuex | Vue 3 官方推荐 |
| **构建工具** | Vite | Webpack | 开发体验好 |

### 部署技术栈

| 组件 | 选型 | 决策理由 |
|------|------|---------|
| **容器化** | Docker + Docker Compose | 一键部署，环境一致 |
| **反向代理** | Nginx | 静态资源、负载均衡 |
| **进程管理** | Supervisor | Python 进程守护 |

## 五、决策权衡记录

| 决策 | 取舍 | 选择的理由 |
|------|------|-----------|
| Python vs Go | 选择 Python | 快速开发优先，后续可用 Rust 重写性能瓶颈 |
| 本地 vs 云端 | 选择本地 | 客户安全刚需，云端是 Phase 2 |
| 简化 RBAC vs 完整 RBAC | 选择简化 | MVP 不需要复杂权限，快速交付 |
| 置信度升 P0 | 升级 | 用户体验关键，信任建立 |
| 数据库查询延后 | 延后 | 技术风险高，不影响核心价值验证 |

## 六、风险与缓解

| 风险 | 缓解措施 |
|------|---------|
| Python 性能瓶颈 | 后续 Rust 重写核心组件 |
| ES 8.12 后续升级 | 保留升级到 ES 9.0 的路径 |
| 功能蔓延 | 严格执行 MVP 边界，每周复盘 |
| 客户需求变化 | 需求放入 Phase 2 清单 |
