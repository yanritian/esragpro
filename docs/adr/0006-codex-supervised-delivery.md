# ADR 0006: Codex 监督的 Agent 交付流程

## 状态

已批准 (Approved)

## 上下文

esRAGPro 的开发流程由多个 AI Agent 协作完成：Codex 负责架构、计划和调度；Claude Code 负责文件操作和实现；其他 Agent（Kimi、Pi、ZCode 等）作为备选执行者。

在 Party Mode (2026-07-23) 讨论中，明确了需要建立一个清晰的交付治理流程，避免以下问题：

- 执行者自行决定提交范围和发布节奏
- 缺少独立验证就把 diff 当作已完成
- Adapter 不可用时静默替换为其他执行者
- 缺少回滚策略和证据记录

## 决策

### 1. 角色与职责

| 角色 | 所有者 | 职责 | 不做什么 |
|---|---|---|---|
| **计划与范围** | Codex | 制定执行计划、定义任务边界、拆分原子提交 | 不直接编辑文件 |
| **调度与租约** | Codex | 分配任务、管理租约、重试和取消 | 不替代执行者做实现决策 |
| **验收与审查** | Codex | 独立检查 diff、测试输出、Docker/HTTP/MCP 和真实运行链 | 不做实现 |
| **Git 操作** | Codex | 暂存、提交、推送、发布 | 不跳过验证 |
| **文件操作** | Claude Code | 计划内文件的创建、修改、删除 | 不决定暂存范围、提交、推送或发布 |
| **递归委派** | 禁止 | Claude Code 不得递归委派其他 Agent | — |

### 2. 每个任务的必要组成

每个执行任务必须包含：

1. **执行计划**: 目标、范围、禁止越界、涉及文件
2. **停止条件**: 什么情况下必须停止并报告
3. **回滚策略**: 如何撤销变更，恢复到什么状态
4. **测试命令**: 验证变更正确的具体命令和预期输出
5. **证据记录**: 命令、退出码、关键输出、Codex 复核结果、commit SHA

### 3. 提交纪律

- **一个行为边界一个提交**: 每个提交只包含一个逻辑变更
- **禁止 mega commit**: 不得把多个不相关变更合并为一个提交
- **提交信息格式**: `docs(scope): description` 或 `feat(scope): description`
- **提交前验证**: 必须通过 whitespace 检查、链接检查和敏感信息检查

### 4. Adapter 不可用处理

当计划中的 Adapter（如 Claude Code）不可用时：

- **Fail closed**: 任务停止，报告不可用原因
- **不得静默替换**: 不得自动切换为其他执行者
- **等待恢复或重新分配**: 由 Codex 决定是等待还是重新规划

### 5. 独立验证

Codex 在 Claude Code 完成文件操作后，必须独立执行：

1. **检查完整 diff**: 确认变更在计划范围内
2. **重跑验证**: whitespace 检查、链接检查、敏感信息检查
3. **运行测试**: 执行计划中定义的测试命令
4. **真实运行链**: Docker 启动、HTTP 请求、MCP 调用等端到端验证
5. **记录证据**: 命令、退出码、关键输出、commit SHA

### 6. 证据记录格式

每个执行包必须在 `.agent-team/control-plane/evidence/` 下创建证据记录，包含：

- Run ID、计划文件、执行者、开始/结束时间
- Changed files 列表
- 命令、退出码和关键输出
- Codex 复核结果
- Commit SHA
- 已知失败和是否为既有问题
- Docker/HTTP/MCP 手工验收结果
- 回滚方式

## 理由

### 为什么选择此方案

1. **职责分离**: 计划和执行分离，避免自我审查盲点
2. **独立验证**: 第二双眼睛检查 diff 和测试结果
3. **可追溯**: 每个变更都有完整的证据链
4. **原子提交**: 便于回滚和审查
5. **Fail closed**: 避免静默降级导致的质量问题

### 替代方案及为何拒绝

**替代方案 1: Claude Code 自行决定提交**
- ❌ 缺少独立验证，容易遗漏测试和链接问题
- ❌ 提交范围可能超出计划
- ❌ 回滚策略可能不完整

**替代方案 2: Adapter 不可用时自动替换**
- ❌ 不同 Agent 的实现风格和能力不同
- ❌ 可能引入计划外的变更
- ❌ 责任边界模糊

## 后果

### 正面后果

1. 每个变更都有独立验证和完整证据链
2. 提交粒度小，回滚容易
3. Adapter 不可用时问题立即暴露，不隐藏
4. 事后审计可以追溯到具体命令和输出

### 负面后果

1. 流程比直接提交更慢
2. 需要维护证据记录文件
3. Codex 需要额外时间做独立验证

### 缓解措施

1. 证据记录采用模板，减少手工编写
2. 简单任务可以合并验证步骤
3. Codex 验证可以并行执行多个检查

## 遵守要求

后续所有开发任务必须遵守：

1. Codex 拥有计划、范围、租约、重试、取消、验收和 Git 所有权
2. Claude Code 是计划内唯一文件操作员，不得递归委派
3. 每个任务必须有执行计划、停止条件、回滚、测试和证据记录
4. 一个行为边界一个提交，禁止 mega commit
5. Adapter 不可用时 fail closed，不得静默替换
