# ADR 0005: 动态世界记忆边界

## 状态

已批准 (Approved)

## 上下文

esRAGPro 的 Agent Memory Plane 当前服务于通用 Agent、企业决策、Coding Agent、IT/SRE/SOC 和历史知识场景。Party Mode (2026-07-23) 进一步讨论了三类复杂物理场景——无人机救援、具身智能和自动驾驶——它们对记忆系统提出了额外的动态性、实时性和证据可追溯要求。

这些场景共同需要一种**动态世界记忆**（Dynamic World Memory）能力：不仅保存静态事实和文档，还要保存来自传感器和事件流的观察、瞬时状态、待验证假设、已验证事实、冲突标记和时间有效证据。

同时必须明确：动态世界记忆是 Memory Plane 的扩展面，不是世界模型、不是规划器、也不是实时控制器。把预测、规划和动作混入记忆层会破坏职责边界、审计能力和安全隔离。

## 决策

### 1. 系统保存六类世界记忆对象

| 对象 | 职责 | 不做什么 |
|---|---|---|
| `WorldObservation` | 记录原始或近原始感知数据，带时间戳和来源 | 不做解释、不做融合、不做预测 |
| `WorldState` | 当前已融合的瞬时状态快照 | 不预测未来、不生成动作指令 |
| `Hypothesis` | 尚未充分证据支撑的待验证命题 | 不直接作为事实返回、不静默覆盖其他对象 |
| `VerifiedFact` | 经证据充分支撑的事实，带证据引用链 | 不永久不变，必须可被新证据撤销或取代 |
| `EvidenceRef` | 指向原始数据、传感器读数、文档或工具输出 | 不做推理，不做语义解释 |
| `ContextPack` | 为 Agent 或 LLM 组装的上下文切片 | 不包含推理结果、不包含动作指令 |

**Observation、Hypothesis 和 Verified Fact 不得混存或互相静默覆盖。** 状态迁移必须显式，必须保留审计轨迹，必须可被回溯。

### 2. 职责边界

| 职责 | 归属 | 不归属 |
|---|---|---|
| 记录观察、状态、假设、事实、冲突、历史和证据 | **World Memory** | — |
| 预测下一步状态或物理演化 | World Model（外部） | World Memory |
| 制定任务计划、搜索策略、调度方案 | Agent Plane（外部） | World Memory |
| 发送控制指令、驱动执行器 | Controller（外部） | World Memory |
| 安全兜底、碰撞避免、物理安全/动作约束 | Safety Controller（外部，场景特定实现） | World Memory |
| 企业认证、租户隔离、访问策略、ACL 预过滤 | Enterprise Gateway / Remote Adapter（外部） | World Memory |

World Memory **不执行**预测、规划、动作或安全兜底。它只记录、组织、检索和提供可审计的证据上下文。

### 3. 复杂场景设计原则

无人机救援、具身智能和自动驾驶共享以下设计原则：

- **Edge-first**: 状态融合和关键观察优先在边缘设备或近端节点完成，减少对云端的实时依赖。
- **事件驱动**: 记忆写入由事件触发，不由轮询或定时批量主导。
- **双时间**: 每条记录同时携带 `observed_at`（世界时间）和 `ingested_at`（系统时间），允许事后区分传感器时钟漂移与系统处理延迟。
- **可重放**: 相同输入和相同版本配置下，融合和检索结果必须可重放。

### 4. 合同复用与安全控制器隔离

无人机、具身和自动驾驶**复用同一套观察、状态、假设、事实、证据和时间合同**，但**不复用安全控制器**。

- 安全控制器与具体物理平台和法规强相关，不能抽象为通用组件。
- World Memory 只提供状态和证据，不替代安全控制器的兜底决策。
- 硬实时控制路径不得经过 LLM、RAG、Elasticsearch 或 Neo4j。

### 5. 与现有 ADR 的一致性

- 与 ADR 0001 一致：PostgreSQL 是世界记忆的权威记录，Elasticsearch 和 Neo4j 是查询投影。
- 与 ADR 0002 一致：Enterprise Edition 优先，Edge 形态后续交付。
- 与 ADR 0003 **部分取代**（非完全一致）：ADR 0005 对 ADR 0003 中 `PrincipalContext` 的适用范围作了部分取代。ADR 0003 中 `PrincipalContext`、OAuth/scope、租户和 ACL 预过滤继续约束 Enterprise Gateway、远程 adapter、企业领域 API 和存储查询边界；但通用无权限 Memory Core 的公开领域合同与本地 MCP stdio **不要求** `PrincipalContext`、认证字段或领域授权。企业路径的检索前存储层 ACL 过滤、撤权屏障、审计和 fail-closed 要求不得削弱。详见 [ADR 0003](./0003-identity-acl-and-trust-boundary.md)。
- 与 ADR 0004 一致：动态世界记忆的质量门禁采用证据覆盖率、拒答正确率、新鲜度和幂等性，不使用单一幻觉率指标。

## 理由

### 为什么选择此方案

1. **职责清晰**: 记忆层不越界做预测和规划，保持审计和可追溯能力。
2. **合同统一**: 不同物理场景共享同一套数据合同，降低维护成本。
3. **安全隔离**: 安全控制器与物理平台绑定，不被记忆层抽象替代。
4. **可重放**: 双时间和事件驱动设计允许事后分析和故障复盘。

### 替代方案及为何拒绝

**替代方案 1: 让记忆层直接做预测和规划**
- ❌ 破坏职责边界，审计链断裂
- ❌ 预测模型更新不应影响记忆写入合同
- ❌ 安全兜底不能依赖概率性记忆输出

**替代方案 2: 每个物理场景维护独立数据合同**
- ❌ 维护成本高，无法复用证据和上下文检索能力
- ❌ 跨场景知识迁移困难

## 后果

### 正面后果

1. 动态世界记忆可作为 Memory Plane 的自然扩展，不破坏现有合同。
2. 无人机、具身和自动驾驶可以共享基础设施，专注各自的 Agent 和安全层。
3. 事后分析和审计有完整的双时间和证据链。
4. 硬实时控制路径不受 LLM 和检索延迟影响。

### 负面后果

1. 六类对象的状态迁移规则需要严格测试。
2. 边缘到中心的同步需要额外的延迟和一致性设计。
3. 安全控制器的场景特定实现需要独立维护。

### 缓解措施

1. 状态迁移采用显式函数和合同测试，禁止静默覆盖。
2. 边缘融合提供降级策略，断网时仍可本地工作。
3. 安全控制器作为外部依赖，通过标准接口与 World Memory 交互。

## 遵守要求

后续所有世界记忆相关的工作包必须遵守：

1. 不得让 World Memory 直接执行预测、规划或动作。
2. Observation、Hypothesis 和 Verified Fact 不得混存或互相静默覆盖。
3. 硬实时控制路径不得经过 LLM、RAG、Elasticsearch 或 Neo4j。
4. 无人机、具身和自动驾驶复用数据合同，不复用安全控制器。
5. 每条记录必须携带双时间和证据引用。
